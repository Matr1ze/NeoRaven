# F11 输入故障诊断

Windows 的 F11 现使用无边框全屏：通过现有 HWND 的样式、位置和尺寸切换，
不进入 LWJGL 独占全屏，不重建窗口或键鼠设备。使用窗口所在显示器的桌面分辨率／
刷新率，退出时恢复窗口位置和大小。游戏 `fullScreen` 设置保持对应，保存为全屏时
下次启动也进入无边框。其他平台仍使用原版全屏路径。

这是避开窗口重建的预防性改动，不代表已经确定现场故障的唯一原因。

`gradlew.bat runClient` 自动启用诊断；发行版默认关闭，需要 JVM 参数
`-Dneoraven.inputDiagnostics=true` 才开启。

文件位于游戏目录 `logs/input-diagnostics/input-0.log`，旧文件为 `input-1.log`
至 `input-3.log`。每个文件约 8 MiB，循环保留约 32 MiB。开发运行对应
`run/logs/input-diagnostics/`。发生故障后应复制整个目录以及 `logs/latest.log`，
注明故障时间和操作；不需要清除配置或音乐登录。

记录内容：

- 当前 GUI、窗口大小、全屏／激活／可见状态、游戏焦点和鼠标捕获状态。
- Windows HWND、前台窗口、线程焦点和鼠标捕获窗口。
- 仅游戏线程／游戏窗口的 Windows 键鼠消息及焦点、最小化、菜单循环消息。
- 鼠标移动数量，按钮／滚轮及坐标，ESC／F11／右 Shift 等控制键。
- LWJGL 最后一次键鼠事件时间，Minecraft／GUI 消费事件的位置。
- tick／渲染心跳、面板动画是否完成，以及日志队列丢弃计数。

文本字符与可打印按键身份不记录，不监视其他应用的输入。Windows 观察 hook
始终调用下一 hook，不修改、吞掉或注入输入，不自动抢焦点。日志经有界队列异步写入，
不对每个鼠标移动写一行。退出游戏后线程和 native hook 随进程释放。

这些日志不是“所有游戏行为的录像”：不能还原安装诊断之前未记录的操作，
也不能独自说明是哪一个外部程序拦截了实体输入。需要结合现场对照测试。
